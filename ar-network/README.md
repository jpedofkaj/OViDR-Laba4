# AR-лаборатория компьютерных сетей

Сайт показывает передачу одного IP-пакета между выбранными компьютерами или сервером. Есть обычная 3D-сцена и дополненная реальность с маркером Hiro. Поиск неисправностей и задания не включены.

## 1. Быстрый запуск на Windows

1. Полностью распакуйте ZIP-архив. Не запускайте файлы внутри окна архива.
2. Откройте папку `ar-network` в VS Code, PyCharm или Проводнике.
3. Если Python 3 уже установлен, дважды нажмите `start_windows.bat`.
4. Откройте в браузере `http://localhost:8000`.
5. Не закрывайте окно сервера, пока пользуетесь сайтом. Остановить сервер: Ctrl+C.

Если Windows не находит команду `py`, откройте терминал в папке проекта и выполните:

```powershell
python server.py
```

Если Python не найден, установите Python 3 с официального https://www.python.org/downloads/ и включите добавление Python в PATH. Затем заново откройте терминал. Внешние Python-пакеты не нужны, `pip install` выполнять не требуется.

Альтернатива для Linux/macOS:

```bash
python3 server.py
```

Если порт занят:

```powershell
python server.py --port 8001
```

Тогда адрес сайта — `http://localhost:8001`.

Открытие `index.html` двойным нажатием через `file://` не является рекомендуемым запуском: запросы AR к локальным файлам маркера и калибровки могут блокироваться браузером. Используйте сервер.

## 2. Управление

- В списке «Отправитель» выберите ПК1, ПК2, ПК3 или сервер.
- В списке «Получатель» выберите другое конечное устройство.
- Нажмите «Отправить пакет». Жёлтый пакет движется по сети, пройденные соединения становятся зелёными.
- «Пауза» останавливает передачу, «Продолжить» возобновляет её.
- Ползунок меняет скорость от 0,5× до 2× даже во время передачи.
- «Сброс» отменяет передачу, оставляя выбранную пару устройств.
- После доставки нажмите «Повторить передачу» или выберите другую пару.
- Кнопка ⇄ меняет отправителя и получателя местами.
- Пока пакет движется или стоит на паузе, изменение пары отключено. Сначала завершите или сбросьте передачу.
- Кнопки «Отправителя» и «Получателя» определяют, какое поле изменит нажатие на модель компьютера или сервера.
- Нажатие на коммутатор или маршрутизатор показывает его назначение, но не делает его конечным устройством передачи.
- Нажатие и перетаскивание в 3D вращает вид. Колесо мыши изменяет масштаб. «Сбросить вид» возвращает исходную камеру.
- На узком экране панель можно свернуть кнопкой − и раскрыть кнопкой +. В AR это освобождает место для камеры.

## 3. Запуск AR на телефоне

Для камеры на телефоне нужен сайт с HTTPS и разрешение пользователя. Адрес `http://192.168...:8000` по Wi-Fi не решает эту задачу: браузер обычно не даёт такой странице доступ к камере. `localhost` на телефоне обозначает сам телефон, а не ваш компьютер.

Самый понятный вариант для защиты — разместить статические файлы на HTTPS-хостинге. Python при таком размещении не нужен.

### Пример размещения через GitHub Pages

1. Войдите в свой GitHub и создайте репозиторий, например `ar-network-lab`. Для обычного бесплатного аккаунта используйте публичный репозиторий: код и сайт будут доступны другим людям.
2. Через `Add file → Upload files` загрузите **содержимое** папки `ar-network`, сохранив подпапки `vendor` и `assets`. В корне репозитория должен находиться `index.html`, а не ZIP-архив и не внешняя папка `ar-network`.
3. Сохраните загрузку через `Commit changes`.
4. Откройте `Settings → Pages`. В разделе `Build and deployment` выберите `Deploy from a branch`, ветку `main` и папку `/(root)`, затем `Save`.
5. Дождитесь окончания развёртывания. На странице Pages появится HTTPS-ссылка. Откройте её на телефоне во внешнем браузере, а не во встроенном окне мессенджера.

Актуальная инструкция GitHub: https://docs.github.com/en/pages/getting-started-with-github-pages/creating-a-github-pages-site

После размещения:

1. На компьютере откройте `marker.html` и распечатайте страницу. Можно показать маркер на экране компьютера вместо печати.
2. На телефоне откройте HTTPS-ссылку сайта.
3. Нажмите «Включить AR», затем «Включить камеру».
4. Разрешите доступ к камере. Направьте заднюю камеру на маркер Hiro.
5. Держите весь чёрный квадрат в кадре, оставьте белое поле вокруг. Используйте ровное освещение без сильных бликов. Не закрывайте рамку пальцами.
6. После появления статуса «Маркер найден» рассмотрите объёмную сеть. Отодвиньте телефон, если часть сети выходит за экран.
7. Выберите отправителя и получателя, отправьте пакет. Модель следует за маркером.

При потере маркера анимация автоматически ждёт его возвращения. После повторного распознавания передача продолжается. Если включена ручная пауза, нужно нажать «Продолжить».

Кадры камеры обрабатываются в браузере: код проекта не отправляет видеопоток на сервер. После перехода обратно в 3D страница перезагружается, и камера освобождается.

### Проверка камеры на компьютере

Камеру можно проверить и на `http://localhost:8000`: включите AR и покажите распечатанный маркер веб-камере. Для защиты с телефоном всё равно проверьте именно телефон и его браузер заранее.

## 4. Топология и примеры

| Устройство | Адрес | Подключение |
| --- | --- | --- |
| ПК1 | 192.168.1.10/24 | Коммутатор 1 |
| ПК2 | 192.168.1.20/24 | Коммутатор 1 |
| ПК3 | 192.168.2.10/24 | Коммутатор 2 |
| Сервер | 192.168.2.100/24 | Коммутатор 2 |
| Маршрутизатор | 192.168.1.1 и 192.168.2.1 | Оба коммутатора |

Пример внутри подсети: ПК1 → коммутатор 1 → ПК2.

Пример между подсетями: ПК1 → коммутатор 1 → маршрутизатор → коммутатор 2 → сервер.

Маршрут вычисляется поиском в ширину по графу топологии. В этой сети без циклов между двумя узлами существует один простой путь. Поиск пути в приложении — способ построить учебную анимацию, а не реализация протокола маршрутизации.

Жёлтый объект условно обозначает IP-пакет. На Ethernet-соединениях пакет передаётся внутри кадра; коммутатор пересылает кадры, маршрутизатор обрабатывает IP-пакет и формирует кадр для следующего участка. ARP, изучение MAC-адресов, DNS, очереди, TTL, заголовки и TCP-handshake здесь не моделируются. Визуализация показывает одну передачу в выбранную сторону, ответ автоматически не отправляется. Чтобы показать обратное направление, поменяйте устройства местами и запустите новую передачу.

## 5. Какие файлы за что отвечают

| Файл | Назначение |
| --- | --- |
| `index.html` | Разметка сайта и элементы управления |
| `styles.css` | Оформление и адаптация к экрану телефона |
| `network.js` | Устройства, соединения и поиск маршрута |
| `app.js` | Создание моделей, AR, выбор устройств и анимация |
| `server.py` | Локальный сервер на стандартной библиотеке Python |
| `start_windows.bat` | Запуск сервера на Windows |
| `marker.html` | Страница для просмотра и печати маркера |
| `assets/hiro.png` | Изображение маркера Hiro |
| `assets/hiro.patt` | Шаблон, по которому AR.js распознаёт Hiro |
| `assets/camera_para.dat` | Файл калибровки для AR.js |
| `vendor/aframe.min.js` | A-Frame 1.6.0 со встроенным Three.js |
| `vendor/aframe-ar.js` | AR.js 3.4.7 для распознавания маркера |

3D-модели построены из геометрических примитивов: отдельные файлы Blender не нужны. Все библиотеки, маркер и калибровка лежат в архиве. Во время локального запуска загрузка JS с CDN не требуется. Для первого открытия размещённого сайта телефон должен иметь доступ к хостингу; автономная установка PWA не реализована.

## 6. Что делать при проблемах

**Появился режим «2D • НЕТ WEBGL».** Браузер не смог создать WebGL 2-контекст. Проект автоматически показывает плоскую схему с той же логикой передачи. Для объёмных моделей и AR откройте сайт на устройстве с поддержкой WebGL 2 и аппаратным ускорением. Резервная 2D-схема сама по себе не является дополненной реальностью.

**Камера не открывается.** Проверьте HTTPS, разрешение камеры в настройках сайта и отсутствие другого приложения, занятого камерой. Откройте сайт напрямую в браузере и перезагрузите страницу.

**Камера работает, сеть не появляется.** Проверьте, что в кадре именно маркер из `marker.html`, видна вся рамка, а статус меняется на «Маркер найден». Покачайте телефон, измените расстояние, устраните блики. Если на хостинг не загрузились `assets/hiro.patt` и `camera_para.dat`, распознавание не заработает.

**Сеть слишком большая.** Отодвиньте телефон. Размер AR-модели задаётся в `app.js` строкой `anchor.setAttribute('scale','.38 .38 .38')`: уменьшение трёх одинаковых чисел уменьшает модель.

**Кнопка отправки недоступна.** Выберите разные устройства. Во время текущей передачи сначала нажмите «Сброс» или дождитесь доставки.

**После редактирования показывается старый код.** Перезагрузите страницу с очисткой кэша (Ctrl+F5 на компьютере). Проверьте, что редактируете папку, из которой запущен сервер.

## 7. Как показать проект на защите

1. Показать распечатанный маркер и объяснить, что он задаёт положение виртуальной сети.
2. Открыть AR на телефоне и показать привязку модели при перемещении камеры.
3. Отправить пакет ПК1 → ПК2: маршрут остаётся в первой подсети.
4. Отправить пакет ПК1 → сервер: маршрут проходит через маршрутизатор.
5. Показать паузу, изменение скорости и обратную передачу.
6. Убрать маркер из кадра и вернуть: передача ждёт восстановления отслеживания.
7. Объяснить назначение HTML, CSS, JavaScript и Python в проекте.

Практическая часть реализует считывание маркера. Для полного отчёта по методичке дополнительно нужны анализ систем по минимум семи характеристикам и описание 3–4 сценариев применения AR. Балл выставляет преподаватель.

## 8. Проверки и ограничения

При подготовке кода проверены синтаксис JavaScript, маршруты всех 16 пар конечных устройств (включая совпадающие), обратные маршруты и отсутствие пути к неизвестному узлу. Проверка интерфейса в доступном браузере выполнялась в резервном 2D-режиме, поскольку в нём недоступен WebGL 2. Проверены запуск передачи, пауза, продолжение, сброс и запрет передачи самому себе. Полноценные 3D-рендеринг и распознавание маркера физической камерой должны быть проверены на целевом устройстве; такая проверка здесь не выполнена.
